[30/09/2026] CONCEPTO — Dashboard
Qué es: panel que reúne datos en una sola pantalla para entender algo
  de un vistazo y tomar decisiones (KPIs, gráficos, tablas, filtros).
Por qué en el portfolio: es lo que más se hace en un trabajo real de
  frontend. Demuestra APIs, estados, componentes reutilizables, gráficos,
  filtros, autenticación y tipado.

[30/09/2026] DECISIÓN — Temática: cafetería de especialidad
Por qué: tiene patrones de datos interesantes (horarios pico, fines de
  semana, estacionalidad), variedad de categorías y cualquiera lo
  entiende en 5 segundos. También sirve para vender paneles a comercios.

[30/09/2026] DECISIÓN — Datos simulados con estadísticas preagregadas
Qué es: el script de seed guarda los pedidos y además resúmenes diarios
  (colección dailyStats).
Por qué: el panel lee pocos documentos en lugar de miles. Menos lecturas
  de Firestore = menos costo y carga más rápida.
Concepto para entrevistas: "desnormalización" / "preagregación".

[30/09/2026] DECISIÓN — Botón "Entrar como demo"
Por qué: un recruiter no se va a registrar para ver un proyecto. Acceso
  en un clic, con usuario de solo lectura.

[30/09/2026] STACK — Recharts
Qué es: librería de gráficos para React.
Para qué lo usé: el gráfico de línea de evolución de ventas (por hora o
  por día, con el período anterior punteado y el mejor punto en caramelo).
Por qué: la más usada en React, con componentes declarativos.
Lo que aprendí: en Recharts 3 accessibilityLayer viene activado por
  defecto y el componente Cell está deprecado (se reemplaza por la prop
  shape). Los atributos SVG que genera no leen variables CSS de forma
  confiable, así que los colores del gráfico se repiten en src/lib/theme.ts.
  El dot personalizado se tipa con DotItemDotProps.
Cambio de plan: el mapa de calor y las categorías quedaron en HTML/CSS
  propio (grilla y barras con etiqueta directa). Recharts no tiene heatmap
  y las barras HTML se leen mejor con lector de pantalla.

[30/09/2026] STACK — TanStack Query (react-query)
Qué es: librería para manejar datos remotos (caché, carga, errores,
  reintentos).
Para qué lo usé: todas las lecturas de Firestore.
Por qué: aparece en ofertas reales y evita manejar loading/error a mano.
Lo que aprendí: la queryKey incluye el origen de datos y el rango
  (["stats", "demo", desde, hasta]); cambiar de período es cambiar de
  clave, y volver a uno ya visto sale de la caché al instante. Para
  "Regenerar" se usa useMutation y, al terminar, setQueryData actualiza la
  caché del resumen sin volver a pedirlo.

[30/09/2026] STACK — Firebase Auth + Firestore + Admin SDK
Para qué lo usé: login, base de datos y verificación del token en la
  API Route antes de llamar a la IA.
Lo que aprendí: (completar; ej.: reglas de seguridad de Firestore)

[30/09/2026] STACK — Zod
Qué es: librería de validación de datos con tipado para TypeScript.
Para qué lo usé: validar lo que llega de Firestore y de la IA.
Lo que aprendí: un solo esquema sirve para tres cosas: el tipo de
  TypeScript (z.infer), la validación en tiempo de ejecución (parse /
  safeParse) y, con betaZodOutputFormat, el formato de salida que se le
  exige a Claude. También valida las respuestas de /api/summary en el
  cliente.

[30/09/2026] STACK — API de Claude (@anthropic-ai/sdk)
Para qué lo usé: resumen semanal con insights, desde un Route Handler
  de Next.js.
Seguridad: API key solo en variables de entorno del servidor. Límite de
  5 resúmenes por usuario por día y caché por semana para controlar
  costos.
Lo que aprendí: modelo claude-opus-5-5 con client.beta.messages.parse +
  salida estructurada (Zod), thinking adaptativo y effort "medium". Se
  activa fallbacks: "default" (beta server-side-fallback-2026-07-01): si
  los clasificadores de seguridad rechazan el pedido, la API lo reintenta
  en otro modelo. Hay que revisar stop_reason === "refusal" antes de leer
  la respuesta. El prompt recibe un JSON chico con las estadísticas de la
  semana (no los pedidos crudos) y pide usar solo números presentes.
  Controles de costo: caché por semana e idioma, 5 regeneraciones por
  usuario por día y tope global diario (AI_GLOBAL_DAILY_CAP).

[30/09/2026] HERRAMIENTA — Vitest
Para qué lo usé: tests de las funciones de cálculo de KPIs.
Lo que aprendí: 17 tests (tests/): totales con corte horario, variación y
  tendencia, categorías, mapa de calor y franja pico, rangos de fechas, y
  que el generador de demo sea determinístico y coherente. La config va en
  vitest.config.mts (con .ts avisaba por ESM en un paquete CommonJS) y
  replica el alias @/ de tsconfig.

[30/09/2026] HERRAMIENTA — playwright-cli (@playwright/cli 0.1.22)
Qué es: CLI de Playwright para manejar un navegador desde la terminal
  (abrir páginas, snapshots, clicks, capturas, emular tema/mobile).
Para qué lo usé: queda instalado (global + navegador con
  `playwright-cli install-browser`) para verificar visualmente el
  dashboard: desktop 1440, mobile 390, claro/oscuro, reduced-motion.
Por qué esto y no otra cosa: permite que Claude Code vea la app real sin
  armar una suite de tests E2E completa.
Lo que aprendí / problema que resolví: ya estaba instalado en la última
  versión; faltaba descargar el navegador. Probado con `open about:blank`.

[30/09/2026] HERRAMIENTA — MCP en Claude Code (context7, Claude Docs)
Qué es: servidores que le dan a Claude Code acceso a herramientas externas.
Para qué lo usé: context7 para consultar la documentación actualizada de

Por qué: evita usar APIs desactualizadas de memoria.

Para qué lo usé: chequeé los tokens del brief con un script de Node antes

  texto sobre accent 5.63 / 6.87 → todo OK.
  border/bg 1.24 / 1.39 → FALLA para controles.
Lo que resolví: el border queda solo decorativo (cards, filas) y se agregó
  el token border-strong #948070 / #806C5C (3.32–3.65 / 3.40–3.66) para
  inputs, chips y controles. Actualizado en el brief y en CLAUDE.md.

[30/09/2026] DECISIÓN — Brief: escala del mapa de calor y línea de ventas

Qué pasó: dependencias instaladas OK (firebase, firebase-admin,

[30/09/2026] DECISIÓN — Modo demo por defecto + Firebase opcional
Qué es: sin variables de entorno, la app genera los datos en el navegador
  con un generador determinístico (src/lib/demo/generator.ts): 60 días de
  pedidos relativos a hoy, en hora de Buenos Aires. Con NEXT_PUBLIC_FIREBASE_*
  lee Firestore. Las dos fuentes cumplen la misma interfaz DataSource.
Por qué: permite publicar en Vercel ya, sin esperar el proyecto de
  Firebase, y la demo nunca "envejece" (siempre muestra la semana actual).
Concepto para entrevistas: "patrón repositorio / inyección de la fuente
  de datos"; PRNG con semilla (mulberry32 + hash FNV de la fecha).
Detalles realistas del generador: sábados de 17 a 19 h con pico, medialunas
  que se agotan antes de las 11 h los domingos, bebidas frías que suben en
  primavera, un nivel distinto por semana.

[30/09/2026] DECISIÓN — Resumen sin IA calculado con reglas
Qué es: si no hay ANTHROPIC_API_KEY, /api/summary arma los 3 hallazgos con

  cruzado con stock, faltantes antes del mediodía). El ticket dice
  "Modo demo · sin IA" y el botón Regenerar no aparece.
Por qué: la demo pública muestra el panel completo y es honesta sobre de

[30/09/2026] CONCEPTO — "Hoy" contra el mismo día de la semana pasada
Qué es: un martes a las 20 h se compara con el martes anterior hasta las
  20 h (se usan las ventas por hora de dailyStats). Los rangos de 7/30 días
  se comparan con el bloque previo de igual duración.
Por qué: comparar el día en curso contra un día completo siempre daría
  "baja"; y un martes contra un lunes mezcla patrones distintos.

[30/09/2026] PROBLEMA — Lint de React 19: setState dentro de useEffect
Qué pasó: la regla react-hooks/set-state-in-effect marcó leer
  localStorage/sessionStorage en un efecto y copiarlo al estado (renders
  en cascada).
Solución: hook useStoredValue (src/lib/storage.ts) con
  useSyncExternalStore: el almacenamiento se trata como una fuente externa
  y React lo lee sin efectos. El servidor devuelve null (= "cargando").

[30/09/2026] STACK — next/font/google
Para qué lo usé: Fraunces (con eje óptico), Space Grotesk y JetBrains Mono
  como variables CSS. Se descargan en el build y se sirven desde el mismo

[30/09/2026] PROBLEMA — Datos de demo poco creíbles en la primera versión
Qué pasó: al revisar con playwright-cli el ticket promedio daba US$ 6 y las

Solución: más productos por pedido (ticket ~US$ 10,40) y un factor por
  semana. También: la regla del resumen elegía un producto chico

[30/09/2026] PROBLEMA — El borde dentado del ticket se leía al revés
Qué pasó: el papel (#FFFDF8) era casi igual a la card (#FFFBF5); se veían

[30/09/2026] PROBLEMA — Comillas invertidas en un comando de bash
Qué pasó: al armar texto markdown dentro de comillas dobles de bash, las
  `comillas invertidas` se ejecutaron como comandos. No hubo daño (fallaron
  solos), pero rompió el CLAUDE.md, que se reescribió.
Lo que aprendí: para texto con markdown, usar un editor de archivos o un
  heredoc con comillas simples ('EOF'), nunca comillas dobles.

[30/09/2026] PROBLEMA — next/font/google falla con Turbopack en Vercel
Qué pasó: el build en Vercel cortó con "Can't resolve

[30/09/2026] PROBLEMA — ERR_REQUIRE_ESM en /api/summary (500 en Vercel)
Qué pasó: firebase-admin/auth → jwks-rsa hace require() de jose, que es solo
  ESM. El runtime de Vercel no lo admite, ni siquiera fijando Node 22
  (engines.node = "22.x", que igual quedó configurado).
Solución:
  1. El ID token de Firebase se verifica con jose directamente
     (src/lib/firebase/verify-token.ts): firma con las claves públicas de
     Google, issuer https://securetoken.google.com/<proyecto> y audience
     <proyecto>. Es el método que documenta Firebase para librerías JWT
     de terceros.
  2. firebase-admin se importa de forma dinámica, solo si hay credenciales:
     en modo demo no se carga nunca.
Lo que aprendí: un error que no aparece en local puede venir del runtime
  del hosting; los logs de la función (`vercel logs --json`) muestran el
  stack completo.

[01/10/2026] STACK — Proyecto de Firebase "grano-co-dashboard"
Qué se armó (casi todo con Firebase CLI):

[01/10/2026] DECISIÓN — Refresco horario con GitHub Actions
Problema: en Firestore los datos quedan congelados el día del seed; en una
  semana "Hoy" estaría vacío (en modo demo no pasa porque se generan al vuelo).
Solución: .github/workflows/refresh-data.yml corre cada hora
  `npm run seed -- --days 1` (ayer y hoy, ~300–450 docs). Como los pedidos
  son determinísticos, pisa los mismos documentos.
Costo: ~11.000 escrituras por día, dentro de las 20.000 gratis de Firestore.
Por qué Actions y no Vercel Cron: el plan Hobby de Vercel solo permite
  crons diarios; Actions es gratis en repos públicos y permite cada hora.

[01/10/2026] PROBLEMA — Top-level await en scripts/seed.ts
Qué pasó: tsx lo compila a CommonJS (el package.json no es "type": "module")
  y CJS no admite await en el nivel superior.
Solución: el cuerpo del script va dentro de una función main().

[01/10/2026] PROBLEMA — ADMIN_ONLY_OPERATION al entrar como invitado
Qué pasó: el login anónimo devolvía 400 ADMIN_ONLY_OPERATION. La consulta a
  la API de configuración (identitytoolkit admin v2) mostró que solo estaba
  activo Email/contraseña y que el dominio de Vercel no estaba autorizado.
Solución: PATCH a /admin/v2/projects/grano-co-dashboard/config con la cuenta
  de servicio (signIn.anonymous.enabled = true + authorizedDomains).
Lo que aprendí: Firebase Auth solo acepta logins desde dominios autorizados;
  cada dominio de producción (y uno propio si se agrega) hay que sumarlo.
Incidente: al leer esa configuración se imprimió en la sesión local el
  hashConfig (clave de firma de los hashes de contraseñas). No se subió a
  ningún lado y el proyecto no tiene usuarios con contraseña. Desde ahí, las
  consultas a esa API muestran solo los campos necesarios.

[01/10/2026] PROBLEMA — La API de Claude responde 400 por el workspace
Qué pasó: con ANTHROPIC_API_KEY cargada en Vercel, /api/summary devolvía 502.
  En los logs: "This API key is not scoped to a workspace, so this request
  must include the anthropic-workspace-id header".
Solución: variable opcional ANTHROPIC_WORKSPACE_ID → se manda como header
  anthropic-workspace-id (defaultHeaders del cliente del SDK). La otra salida
  es crear la clave dentro de un workspace en la consola de Anthropic.
Después apareció un 401 "API key is invalid": la clave cargada ya no servía.
  El usuario creó una clave nueva y la cargó desde su terminal con
  `vercel env add ANTHROPIC_API_KEY production --sensitive` (el `!` de Claude
  Code no sirve: corre en modo no interactivo y no puede pedir el valor).
Estado: RESUELTO. ANTHROPIC_WORKSPACE_ID + clave nueva en Vercel. Verificado en
  producción: el resumen lo escribe Claude (~17 s la primera vez, después
  sale de la caché), con el sello "IA" y "Claude · API de Anthropic".
Lo que aprendí: Claude cruzó datos que las reglas no cruzaban (medialunas con
  stock para 0,4 días + faltante del domingo; cold brew + leche de avena) y
  usó solo números del JSON, como pide el prompt.

[01/10/2026] DECISIÓN — Si Claude falla, el panel no muestra error
Qué: al cargar la página (GET), si la API de Claude falla se usa el resumen

[01/10/2026] DECISIÓN — Cabeceras de seguridad y CSP (Fase 3)
Qué: next.config.ts agrega Content-Security-Policy, X-Content-Type-Options,
  X-Frame-Options DENY, Referrer-Policy y Permissions-Policy; quita
  X-Powered-By. HSTS lo pone Vercel.
CSP: variante "sin nonces" de la guía de Next 16 (script-src con
  'unsafe-inline' por los scripts inline de Next). Con nonces todas las
  páginas pasarían a renderizarse por pedido; SRI es experimental.
  connect-src solo a identitytoolkit, securetoken y firestore.googleapis.com;
  frame-src 'none'; frame-ancestors 'none'.

[01/10/2026] PROBLEMA — getAuth() cargaba apis.google.com (CSP lo bloqueaba)
Cómo se encontró: Lighthouse (best-practices 92, error de CSP en consola).
  La prueba con playwright-cli no lo vio porque solo miraba errores.
Causa: getAuth incluye el resolver de popup/redirect, que descarga gapi.
Solución: initializeAuth con persistencia indexedDB/localStorage y sin
  resolver. Verificado: 0 pedidos a apis.google.com, consola vacía, la sesión
  sobrevive a recargar y "Salir" funciona.
Lo que aprendí: para revisar CSP hay que escuchar todos los mensajes de
  consola (page.on("console")), no solo los errores.

[01/10/2026] DECISIÓN — Límite por IP en "Regenerar"
Por qué: las cuentas anónimas de Firebase se crean gratis con cada sesión,
  así que el límite de 5 por usuario se podía esquivar. Ahora también hay 10
  por IP por día, más el tope global diario.

[01/10/2026] PROBLEMA — npm audit: 4 altas en @grpc/grpc-js
Causa: el SDK web de Firebase (12.19.0, la última) trae grpc-js 1.9.16. npm
  sugería bajar firebase a la 9.x (sin sentido).

  firebase-admin; cambio menor, compatible). Quedan 2 moderadas en uuid
